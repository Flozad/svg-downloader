Wenn du nur eine Sache liest

Warum der Browser es nicht einfach für dich speichert

Ein SVG auf einer modernen Seite ist fast nie eine Datei, die an einer Adresse liegt. Es ist eines von vier Dingen, und jedes hebelt Bild speichern unter… auf seine Art aus: Inline-<svg>-Markup, direkt ins HTML gezeichnet, ohne URL dahinter; ein CSS-background-image, das der Browser als Dekoration behandelt; eine Sprite-<use>-Referenz, die in ein verstecktes Dokument zeigt; oder eine <img>-Quelle, die ein data:-URI sein kann, den das Speichern-Menü verstümmelt.

Jedes Tutorial hier funktioniert darunter gleich: das lebende DOM lesen, auflösen, was jeder Vektor wirklich ist, den fehlenden xmlns-Namensraum reparieren und dir eine eigenständige Datei geben. Deshalb ist es der Methode egal, auf welche der vier du gerade gestoßen bist.
